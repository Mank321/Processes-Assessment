WORLD RENDERING PROBLEMS
14-15 June - When making the scene changing program, I wrote up a function to load the tutorial,
and a seperate function to load the market. I later found this to be repetitive as
I would need to create a function for each level. So I decided to compress the functions
into one that could handle everything. This lead me to creating a class each for the tutorial,
market, and monster levels, which should allow me to turn everything on and off easily. 
When switching scenes, I got an error that manager.new_scene didn't exist. I fixed this by
setting market_world and tutorial_world to None at the very begining, then in the switch_scenes
function, I checked if the new_scene was None, then checked the old_scene's gate name to discover
what the new_scene should be, then initialized the correct scene.
I had to change the entities lists from game_state to the new class, in the collision detectors.

It went from:
def load_market(self):
        if self.game_state.location == 'tutorial':
            for entity in self.game_state.tutorial_entities:
                entity.disable()
            for entity in self.game_state.tutorial_colliders:
                entity.disable()
        if hasattr(self.game_state, 'market_entities'):
            for entity in self.game_state.market_entities:
                entity.enable()
            for entity in self.game_state.market_colliders:
                entity.enable()
        else:
            create_market_world(self.game_state)
        print_on_screen('-Market-', position=(-0.1,0.45), scale=3, duration=3)
        self.game_state.location = 'market'
        self.player.position = (0,0,0)

To:
def switch_scenes(self, new_scene, old_scene):
        """."""
        scene = old_scene.gate.name.split('.')[1]

        if new_scene == None:
            if scene == 'market':
                self.market_world = MarketWorld(self.game_state)
                new_scene = self.market_world

        new_scene.enable()
        for entity in new_scene.entities:
            entity.enable()
        for entity in new_scene.colliders:
            entity.enable()
        old_scene.disable()
        for entity in old_scene.entities:
            entity.disable()
        for entity in old_scene.colliders:
            entity.disable()
        
        print_on_screen(f'--{scene.title()}--', position=(-0.1,0.45), scale=3, duration=2)
        self.game_state.location = scene
        self.player.position = (0,0,0)

WORLD CREATION PROBLEMS
FIXED: When creating the forest in the tutorial area, I started with a massive list containing the pre-chosen position of each tree. Then I looped through the list to plant each
tree. This was incredibly inefficient, so I create a 2d map array which had the entire forest plotted out in a dozen lines. I initially filled the entire area in with
over a thousand trees, but this tanked the framerate down to 20fps, so I knew I couldn't do it that way without breaking a requirement.
Instead, I shrunk the forest down to a minimum size with just having the trees as border walls, and shrunk the main perimeter wall to fit the new forest size.
It took a bit of time to get the exact coordinates right and the tree spacing and map array. 

COMBAT SYSTEM PROBLEMS
FIXED: When creating the combat system, I added in the monster, gave it a hitbox, damage, and health, and gave it movement and distance checks, allowing it to move up to the player
and attack them when close enough, taking away 1 health point per second. But when I tried to have the player attack the monster in retaliation, nothing happened. After a bit
of debugging, I realised I was checking to see if the mouse.hovered_entity had health. I initially thought the entity was the monster itself, but it was actually the collision
box that the player was hitting, as I discovered when I gave the collision box a name and printed it when attacking. I thought of adding the monster stats right into the
collision box entities, but that felt wrong, so I attempted to create an on_click method for the monster, but that ended up not being called, or calling as soon as the player
was in range. I thought about going back to the collision box idea, but thought of an idea to fix the monster not being instantly destroyed by only calling the on_click method
when the player actually clicked on the monster. I still ran into a problem where the code was trying to find a monster that had been destroyed when checking for collisions.
To fix this, I decided to allow the player to walk through monsters, meaning I didn't need to check their hitbox
-
FIXED: When trying to use a gate, since the monster was destroyed, it couldn't be disabled, creating errors. To fix this, I tried changing the switch_scenes method from using an entities
list given by TutorialWorld, to going through every child of TutorialWorld itself, and going through every child of those children to catch the collision boxes. This allowed
me to go through the gate, but didn't disable anything. Instead, I parented everything in the world to the TutorialWorld entity, allowing me to disable everything with one line.

PLAYER SYSTEMS
FIXED: When building the levelup system, I created a healthbar in the UI, and created a method to levelup. When leveling up,
the player's health returns to max, and when printed out, it does. But on screen, and when fighting a monster,
the UI healthbar doesn't change at all, neither the value or max_value. Through debugging, I discovered
the problem came from the invoke() function from the monster class that deals damage to the player. I intially replaced
it with a simple health -= damage * time.dt, but this resulted in many decimal places. So in the ui_state update method,
I simply made it display a rounded number.
